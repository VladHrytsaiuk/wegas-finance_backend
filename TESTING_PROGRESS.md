## 🚀 Подальші кроки та підготовка до PWA

Поточного рівня покриття (~45-50% загалом, >80% для критичних утиліт) цілком достатньо для початку активної розробки PWA додатка. Проте, для забезпечення стабільності мобільного досвіду, рекомендується наступне:

### 1. Синхронізація та Offline-режим
- [ ] **Conflict Resolution:** Додати тести для сценаріїв, коли два пристрої редагують одну транзакцію офлайн, а потім синхронізуються.
- [ ] **Background Sync:** Протестувати поведінку API при масових запитах під час фонової синхронізації PWA.

### 2. Покращення безпеки сесій
- [ ] **Token Refresh:** Реалізувати та ретельно протестувати механізм оновлення токенів (Refresh Tokens), оскільки PWA сесії зазвичай тривають довше.
- [ ] **Rate Limiting:** Додати обмеження кількості запитів (Rate Limiting) на рівні API, щоб захистити сервер від некоректної поведінки клієнтських скриптів або атак.

### 3. Тестування продуктивності (Performance)
- [ ] **Latency Simulation:** Провести тести з імітацією високої затримки мережі (Slow 3G), що критично для мобільних користувачів.
- [ ] **Large Datasets:** Протестувати швидкість завантаження списку транзакцій при їх кількості > 10,000.

### 4. Інтеграційне E2E тестування
- [ ] **Playwright/Cypress:** Після розробки базового фронтенду PWA, додати E2E тести, які проходять повний шлях користувача (Login -> Add Transaction -> Check Dashboard).

## Як запускати тести

```bash
# Запуск всіх тестів з покриттям
go test ./... -cover

# Генерація детального звіту
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out -o coverage.html
```
