# WeGaS Finance API

**WeGaS Finance** — це сучасний, високопродуктивний бекенд для керування сімейними фінансами, написаний на мові Go. Проєкт фокусується на автоматизації обліку, багатокористувацькому доступі та наданні глибокої аналітики для ефективного фінансового планування.

## 📝 Про проєкт
Проєкт реалізовано за багатошаровою архітектурою (Layered Architecture), що забезпечує чітке розділення відповідальності між обробкою запитів (Controllers), бізнес-логікою (Services) та взаємодією з базою даних (Repositories). Особливістю проєкту є підтримка сімейних аккаунтів з розділенням ролей (Батьки/Діти), глибока інтеграція з Monobank API для автоматичної синхронізації транзакцій та гнучка система обліку активів і комунальних платежів. Система також може працювати як Windows-сервіс, що робить її зручною для локального хостингу.

## 🛠 Стек технологій
*   **Language**: Go (v1.25.4+)
*   **Web Framework**: [Gin Gonic](https://github.com/gin-gonic/gin) — для швидкого та надійного роутингу.
*   **ORM**: [GORM](https://gorm.io/) — для мапінгу об'єктів на реляційну схему.
*   **Database**: SQLite (через `glebarez/sqlite`) — pure-Go реалізація, що не потребує CGO, ідеальна для портативності.
*   **Auth**: JWT (JSON Web Tokens) для захисту ендпоінтів.
*   **Documentation**: Swagger (swaggo/swag) для автоматичної генерації API-специфікації.
*   **Integrations**: Monobank API (Banking), Telegram Bot API (Feedback system).
*   **Format Handling**: PDF parsing (для банківських виписок), Excelize (експорт даних).

## ✨ Ключові фічі
*   🏦 **Авто-синхронізація з банками**: Повна підтримка Monobank (рахунки, картки, "банки") з фоновим оновленням транзакцій.
*   👨‍👩‍👧‍👦 **Сімейний доступ**: Система ролей, де діти мають обмежений доступ до загальних фінансів, а батьки керують бюджетом всієї родини.
*   📊 **Аналітичний Дашборд**: Тренди доходів/витрат, ТОП-категорії, деталізовані звіти за періоди та рахунки.
*   🎯 **Фінансові цілі**: Можливість ставити цілі для накопичень з прив'язкою до реальних банківських рахунків.
*   🏠 **Комунальний облік**: Трекінг лічильників, історія показників та фіксація оплат.
*   🚗 **Облік активів**: Керування майном, транспортними засобами (з трекінгом пробігу) та зберігання супровідних документів/фото.
*   📝 **Списки та Вішлисти**: Спільні списки покупок та система "бажань" з можливістю резервування подарунків членами родини.

## 📂 Структура проєкту
```
backend/
├── controllers/    # Обробка HTTP запитів, валідація DTO, взаємодія з Gin контекстом.
├── services/       # Ключова бізнес-логіка, інтеграція з зовнішніми сервісами (Mono, TG).
├── repositories/   # Ізольований рівень роботи з БД через GORM.
├── models/         # Опис доменних моделей (entities), структур бази даних та DTO.
├── database/       # Конфігурація SQLite, логіка автоматичних міграцій.
├── routes/         # Реєстрація роутів та підключення Middlewares.
├── middlewares/    # Автентифікація користувачів (JWT) та CORS налаштування.
├── pkg/            # Глобальні утиліти: конфігурація, Telegram клієнт.
├── utils/          # Хелпери: криптографія, парсери банківських виписок, сідери даних.
├── uploads/        # Зберігання завантажених користувачами файлів (чеки, документи, фото).
└── main.go         # Точка входу: ініціалізація DI-контейнера, запуск сервера та шедулерів.
```

## ⚙️ Локальний запуск
1.  **Налаштування середовища**:
    Скопіюйте приклад конфігурації та заповніть необхідні змінні (ключі API, секрети):
    ```bash
    cp .env.example .env
    ```
2.  **Завантаження залежностей**:
    ```bash
    go mod download
    ```
3.  **Запуск сервера**:
    ```bash
    go run main.go
    ```
    *При першому запуску база даних SQLite (`finance.db`) буде створена автоматично, а міграції застосуються до неї миттєво.*

## 📖 API Документація
Проєкт інтегрований зі **Swagger**. Документація генерується на основі декларативних коментарів у коді.

*   **Генерація/Оновлення**: `swag init`
*   **Swagger UI**: Доступний за адресою `http://localhost:8080/swagger/index.html` після запуску сервера.

UI дозволяє тестувати всі методи API прямо з браузера. Для захищених роутів скористайтеся кнопкою **Authorize** та введіть ваш JWT токен.
